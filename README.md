# LifeMentor Agent

## 项目定位

本项目要实现一个面向个人生活与长期目标管理的 Agent。

这个 Agent 的核心不是简单记笔记或维护待办，而是：

- 认识用户是谁
- 理解用户想成为什么样的人
- 围绕用户的目标指导用户做事
- 把生活中不同的事情拆分成可持续跟踪的 `事项`
- 从日常对话中自动提取 `事项`、进展和下一步行动
- 持续记录、提醒、跟进、复盘和归档

## 核心理解

用户在生活中会同时推进很多事情，这些事情不能混在一起管理。

因此，Agent 需要把每一件持续发展的事情都视为一个 `事项`。一个 `事项` 可以是：

- 一个项目
- 一个长期目标
- 一个待解决的问题
- 一段关系
- 一个习惯养成过程
- 一项阶段性任务

每个 `事项` 都有自己的目标、状态、上下文、最新进展、下一步动作和处理策略。所有 `事项` 共同构成用户当前生活状态的整体结构。

## Agent 的核心能力

### 1. 认识用户

Agent 要逐步建立对用户的理解，包括：

- 用户当前是什么样的人
- 用户处在什么人生阶段
- 用户在意什么
- 用户有哪些长期目标和短期目标
- 用户当前最重要的矛盾、压力和机会是什么

这些信息不应依赖一次性问卷，而应通过长期互动逐步完善。

### 2. 理解用户想成为什么样的人

Agent 需要理解用户的目标状态，而不仅是表面的任务列表。

例如：

- 用户想成为怎样的人
- 用户想拥有怎样的生活状态
- 用户想建立哪些能力、习惯、关系和成果
- 当前正在做的事与这些目标之间是什么关系

Agent 后续的指导、提醒和建议，都应尽量围绕这些目标展开。

### 3. 把生活中的事项抽象为 `事项`

用户的生活里有很多并行事项，每件事都需要被单独梳理。

Agent 需要能够：

- 从对话中识别新的 `事项`
- 判断某段对话属于哪个已有 `事项`
- 为每个 `事项` 建立独立记录
- 维护 `事项` 的阶段、状态和上下文

这意味着系统的核心记录单位不是单条消息，而是 `事项`。

### 4. 从日常对话中自动提取信息

Agent 需要从用户的日常对话中自动提取以下信息：

- 新出现的 `事项`
- 某个 `事项` 的最新进展
- 遇到的阻碍
- 用户的态度变化
- 已经做出的决定
- 明确的下一步动作
- 需要提醒的时间点

也就是说，用户不需要每次都显式说“请记录”，Agent 应该能在对话中自动识别出值得沉淀的信息。

### 5. 记录并跟踪每个 `事项` 的进展

每个 `事项` 都应维护结构化信息，例如：

- 标题
- 背景
- 为什么重要
- 当前状态
- 最新进展
- 风险或阻碍
- 下一步动作
- 建议执行时间
- 最近一次更新时间

Agent 需要持续更新这些信息，而不是反复生成互相割裂的记录。

### 6. 按 `事项` 的类型和进展给出不同处理方式

不同事情需要不同策略，不能统一处理。

例如：

- 对明确且简单的事，重点是推进执行
- 对复杂问题，重点是拆解和规划
- 对不确定的问题，重点是调研和判断
- 对长期事项，重点是节奏管理和周期跟进
- 对容易拖延的事，重点是提醒、压缩下一步和降低行动门槛

因此，每个 `事项` 都应有自己的处理方式，并且这种处理方式会随着进展变化而调整。

### 7. 主动提醒用户下一步该做什么，以及什么时候做

Agent 不应只被动响应。

它需要能够根据 `事项` 当前状态主动判断：

- 用户下一步应该做什么
- 最适合在哪个时间点做
- 如果没有推进，何时提醒
- 如果卡住了，应该提供什么建议

提醒的重点不是机械催办，而是结合上下文给出合理行动建议。

### 8. 定期 Review

除了逐条跟踪 `事项`，Agent 还需要做周期性回顾，例如：

- 今天有哪些 `事项` 有进展
- 哪些 `事项` 被长期搁置
- 当前主要精力被哪些事情占据
- 这些事情是否仍然服务于用户目标
- 哪些 `事项` 应该继续推进、降级、暂停或结束

### 9. 归档

当某个 `事项` 完成、结束、失效或长期暂停后，Agent 需要将其归档。

归档后仍应保留：

- 关键过程
- 重要决策
- 结果
- 经验教训

这样既能保持当前工作区清晰，也能保留长期记忆。

## Agent 的工作流

这个 Agent 的工作流可以概括为：

1. 通过日常对话逐步认识用户
2. 建立并持续更新用户目标模型
3. 从对话中识别新的 `事项`
4. 将新信息归入已有 `事项` 或创建新 `事项`
5. 更新每个 `事项` 的进展、状态、策略和下一步
6. 在合适时间主动提醒用户采取行动
7. 定期对所有 `事项` 做 Review
8. 对结束或失活的 `事项` 做归档

## 一句话总结

这是一个以用户目标为中心、以 `事项` 为核心管理单位、能够从日常对话中自动提取信息并持续跟踪推进的 Markdown Agent。
