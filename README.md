# Agent Memory

> 一个研究 Agent 如何从“依赖外部材料”走向“依赖内化记忆行动”的仓库。

## 仓库核心

这个仓库讨论的核心不是“怎么存更多信息”，而是：

**Memory 如何帮助 Agent 学会做事，并在做过之后越来越会做。**

我关心的是这样一个问题：

**Agent 能不能像人一样，在陌生任务里先借助外部材料完成行动，再把历史经验逐渐内化为自己的记忆，最终直接根据记忆推导下一步行动。**

所以这里的 Memory，不只是信息存储，而是行动能力的一部分。

## 核心思想

### 1. 从人类学习过程理解 Memory

从人类学习做事的过程看，记忆并不是一开始就完整存在的。

当一个人进入陌生环境，或者第一次做一件从未做过的事情时，他通常不能直接知道下一步该做什么。这个时候，他需要借助外部材料来行动，比如：

- 别人的指令
- 操作手册
- 参考案例
- 公开资料
- 过往示范

他会先学习“先做什么，再做什么，再做什么”，再按照这些参考去执行。

而当同一类事情被反复做过很多次之后，原本依赖外部材料的步骤，会逐渐沉淀成自己的记忆。到了这个阶段，他不再需要每次重新查资料，而是可以直接根据经验和当前情境，推导出下一步行动。

基于这个观察，我目前把 Agent Memory 理解为一个两阶段模型。

### 2. 两阶段 Memory 模型

#### 第一阶段：外部辅助记忆

第一阶段对应的是学习和操作阶段。

在这个阶段，主体还没有形成足够稳定的内部经验，因此需要依赖外部材料来辅助自己完成任务。这一阶段的 Memory 更像是一种外部支架，它不在“脑子里”，而是在环境里。

它可以是：

- 一份指令
- 一套 SOP
- 一篇教程
- 一组案例
- 一份操作手册

第一阶段真正要解决的，不是“怎么回忆”，而是：

- 怎么找到合适的参考材料
- 怎么理解材料里的步骤和约束
- 怎么把参考内容组织成当前可执行的行动
- 怎么在执行过程中留下可复用的经验

所以，第一阶段的核心作用是：

**为陌生任务提供可执行的外部支持。**

#### 第二阶段：内化行动记忆

第二阶段对应的是经验内化阶段。

当一类任务被反复执行之后，原本依赖外部材料的步骤、判断方式和行动顺序，会逐渐沉淀为内部记忆。到了这个阶段，主体不需要每次都重新查找参考内容，而是可以直接根据已有经验进行思考，并推出下一步该做什么。

这一阶段的 Memory 更像是一种内化能力。它的表现通常是：

- 不再强依赖外部材料
- 对步骤和顺序已经形成稳定理解
- 对常见情况有默认判断
- 可以根据上下文直接推出下一步行动
- 行动速度更快，成本更低

所以，第二阶段的核心作用是：

**把历史经验转化为可以直接驱动行动的内部能力。**

### 3. 两个阶段之间的关系

这两个阶段不是割裂的，而是一个连续的演化过程：

1. 在陌生任务中借助外部材料开始行动
2. 在执行过程中积累真实经验
3. 从经验中提炼出关键步骤、判断条件和有效策略
4. 把这些可复用的模式压缩为内部记忆
5. 在下一次类似任务中，直接由记忆支持思考和行动

换句话说：

**Memory 的价值，不只是保存过去，而是减少未来的重复学习。**

### 4. 这对 Agent 的启发

如果把这套模型放到 Agent 上，那么一个好的 Agent Memory 系统至少应该支持两类能力：

- 在陌生任务中，帮助 Agent 借助外部材料完成行动
- 在重复任务中，帮助 Agent 把经验沉淀为长期可调用的能力

所以我更关注的，不是：

- Agent 能存多少上下文

而是：

- Agent 能不能从一次次执行中形成自己的行动记忆

## 第一阶段：外部 Memory 的组织问题

第一阶段真正要解决的一个核心问题是：

**当 Agent 正在处理一件事时，系统应该怎样组织这件事的过程，才能让 Agent 高效知道这件事是什么、已经做到哪里、过去是怎么做的。**

### 1. 用 Matter 作为基本组织单位

我目前的一个基本判断是：

**任何持续推进的事情，都应该以某种形式被组织起来。**

这里先不急着定义得过细，当前可以先统一把这个组织单位叫做 **Matter**。

也就是说：

- 平时做的任何一件事情，都应该归属于某个 Matter
- 一个 Matter 可以很短，很快完成
- 一个 Matter 也可以很长，跨越很多阶段和很多步骤
- 不管 Matter 长短，系统都应该能持续组织它的上下文和进展

如果没有这个统一组织单位，Memory 就会退化成零散记录，Agent 很难知道“这些记录到底属于哪件事”。

### 2. 原始记录是最权威的基础

一个好的第一阶段 Memory 系统，首先应该有 **原始记录层**。

这一层负责记录 Matter 在推进过程中发生的每一次关键事件和进展。它是整个系统最基础、也最权威的一层。

这一层的作用是：

- 记录真实发生过什么
- 记录进展是如何一步步形成的
- 为后续所有组织、总结和展示提供原始依据

所以，原始记录层更像是 Matter 的事实底稿。后面所有更高级的结构，都应该建立在这一层之上。

### 3. 原始记录之上还需要组织层

只有原始记录还不够，因为原始记录往往是连续的、细碎的、时间顺序驱动的。

系统还需要在原始记录的基础上，把这些内容重新组织起来，让它们更容易理解和使用。

这一层可以做的事情包括：

- 按 Matter 聚合记录
- 按时间梳理进展
- 提炼关键节点
- 标记当前状态
- 识别重要决策
- 识别阻碍和未解决问题
- 提炼下一步候选行动

这一步的重点不是“压缩成一句总结”，而是：

**把原始事件流整理成 Agent 可以操作的 Matter 结构。**

### 4. 还需要适合 Agent 的表示形式

“记录得下来”和“Agent 能高效使用”是两件不同的事。

所以在组织层之上，系统还需要一层表示层，把已经组织好的内容转换成 Agent 熟悉、易检索、易推理的形式。

这层的形式目前不预设唯一答案，可以包括：

- 纯文本摘要
- 结构化文本
- 知识图谱
- 向量数据库 + Embedding
- 多种形式组合的混合表示

这里的关键不是用哪一种技术名词，而是：

**哪一种表示方式能让 Agent 在需要时最快拿到足够有用的 Memory。**

### 5. 获取和披露本身也是 Memory 的一部分

即使记录、组织、表示都做好了，如果 Agent 在真正执行任务时拿不到正确的内容，Memory 依然无法发挥作用。

所以第一阶段还必须解决两个问题：

- 应该取回哪些 Memory
- 应该以什么顺序把这些 Memory 交给 Agent

也就是说，第一阶段不只是“存”，而是要形成一条完整链路：

**记录 -> 组织 -> 表示 -> 获取 -> 支持行动**

## 第二阶段：从外部 Memory 到参数化能力

如果说第一阶段解决的是 **如何借助外部 Memory 完成任务**，那么第二阶段要解决的就是：

**如何把第一阶段里积累下来的经验，真正内化到模型本身。**

### 1. 第二阶段的目标

第二阶段的目标是让模型在面对熟悉任务时：

- 不必每次都重新检索第一阶段的外部材料
- 能直接理解当前处境
- 能基于过去积累的经验推出下一步行动
- 在常见任务上表现出更稳定的行动习惯和判断方式

从这个角度看，第二阶段更像是把第一阶段的显式 Memory，逐渐变成模型内部的隐式能力。

### 2. 第二阶段的输入来自第一阶段

第二阶段并不是凭空产生的，它的训练素材应该主要来自第一阶段积累下来的内容。

这些内容包括：

- Matter 执行过程中的原始记录
- 被整理过的 Matter 结构
- 历史上有效的操作步骤
- 成功的行动轨迹
- 关键判断点和决策方式

换句话说，第一阶段更像是在积累训练材料，而第二阶段则是在把这些材料变成模型能力。

### 3. 第二阶段的核心动作是经验参数化

我目前的判断是，第二阶段最关键的一步是：

**把那些稳定、可复用、已经被验证过的经验，从外部记录中抽出来，再通过后训练写进模型参数。**

这意味着，不是所有第一阶段的原始记录都应该直接进入参数。

更适合被参数化的，应该是那些：

- 高频出现的模式
- 在多个 Matter 里反复验证有效的策略
- 比较稳定的步骤顺序
- 对下一步行动有明确指导价值的判断规则

因此，第二阶段不是简单地“把更多数据喂给模型”，而是要做一次经验筛选和压缩。

### 4. 一个值得重点探索的方向：Agentic RL

在训练方法上，我目前倾向于把第二阶段理解成一种后训练问题。

其中一个重要方向，就是使用 **Agentic RL** 这样的方式来训练模型。

这里的直觉是：

- 第一阶段已经积累了大量与真实任务相关的操作轨迹
- 第二阶段可以把这些轨迹变成训练环境、目标和反馈信号
- 模型通过训练，不只是“知道答案”，而是学会在任务过程中如何一步步行动

如果这样做成功，那么第二阶段得到的就不只是外部可查的 Memory，而是模型参数中真正具备的行动能力。

### 5. 第一阶段和第二阶段的分工

当第二阶段足够成熟之后，Agent 的行为会发生一个重要变化：

- 面对熟悉任务时，优先依赖模型内部已经学到的能力
- 只有在陌生、罕见或不确定的情况下，才回到第一阶段的外部 Memory 系统

也就是说，第一阶段和第二阶段不是互相替代，而是形成分工：

- 第一阶段负责支持陌生任务和经验积累
- 第二阶段负责把成熟经验转化为低成本、高速度的内部能力

## 实验性实践：Matter Manager

`Matter Manager` 不是这个仓库的核心定义，而是我在第一阶段里的一个实验性实现。

它的作用不是代表 Agent Memory 的全部，而是用来验证一个更具体的问题：

**如果第一阶段要围绕 Matter 来组织 Memory，那么系统可以怎么落地。**

### 1. 它在验证什么

`Matter Manager` 主要在验证下面几件事：

- 任何持续推进的事情，是否都可以先归到某个 Matter
- 原始事实记录，是否应该始终作为最权威的底层
- Matter 是否适合用树状结构来组织
- Agent 是否应该按层次读取 Matter，而不是直接读取全部历史

### 2. 它采用的组织方式

在这个实验里，Memory 的组织方式大致是：

- 先有 Matter 分类
- 分类下面有 Matter 名称
- 每个 Matter 挂载自己的原始信息
- 每个 Matter 继续挂载自己的详细历史记录

也就是说，它尝试把零散事件组织成一个可追踪、可浏览、可逐层下钻的 Matter 树。

### 3. 它采用的披露策略

`Matter Manager` 的一个重要假设是：

**Agent 不应该一上来就读取完整历史，而应该先粗后细地查看。**

当前这套实验性披露顺序是：

1. 先看 Matter 的分类
2. 再看 Matter 的名称
3. 再看 Matter 的原始信息
4. 最后在需要时再看详细历史记录

这样做的目的，是让 Agent：

- 先快速定位当前是哪个 Matter
- 再用最小上下文理解这个 Matter 是什么
- 只有在需要细节时，才进入完整历史

### 4. 它的定位

`Matter Manager` 只是当前的一种实验样本。

它可以帮助我验证第一阶段里关于组织、披露和读取策略的一些想法，但它并不等于 Agent Memory 的最终形式，也不应该限制后面更广泛的设计空间。
