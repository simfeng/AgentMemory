# Agent Memory

> 一个研究 Agent 如何从“依赖外部材料”走向“依赖内化记忆行动”的仓库。

## 仓库概述

这个仓库关注的核心问题是：

**Agent 如何像人一样，在陌生任务里先借助外部材料完成行动，再把历史经验逐渐内化为自己的记忆，最终可以直接基于记忆推导下一步行动。**

这里讨论的 Memory，不只是“保存了什么信息”，而是：

**Memory 如何真正帮助 Agent 学会做事。**


## 为什么从人类学习过程来理解 Memory

从人类学习做事的过程看，记忆并不是一开始就完整存在的。

当一个人进入陌生环境，或者第一次做一件从未做过的事情时，他通常不能直接知道下一步该做什么。这个时候，他需要借助外部材料来行动，比如：

- 别人的指令
- 操作手册
- 参考案例
- 公开资料
- 过往示范

他会先学习“先做什么，再做什么，再做什么”，然后按照这些参考去执行。

而当同一类事情被反复做过很多次之后，这些原本依赖外部材料的步骤，会逐渐沉淀成自己的记忆。到了这个阶段，他不再需要每次重新查资料，而是可以直接根据经验和当前情境，推导出下一步行动。

基于这个观察，我目前把 Memory 理解为一个 **两阶段模型**。

## 两阶段 Memory 模型

### 第一阶段：外部辅助记忆

第一阶段对应的是 **学习和操作阶段**。

在这个阶段，主体还没有形成足够稳定的内部经验，因此需要依赖外部材料来辅助自己完成任务。

这一阶段的 Memory 更像是一种 **外部支架**，它本身不在“脑子里”，而是在环境里。它可以是：

- 一份指令
- 一套 SOP
- 一篇教程
- 一组案例
- 一份操作手册

这一阶段的关键不是“回忆”，而是：

- 找到合适的参考材料
- 理解材料里的步骤和约束
- 把参考内容组织成当前可执行的行动
- 按顺序完成任务

所以，第一阶段的核心作用不是替代思考，而是：

**为陌生任务提供可执行的外部支持。**

### 第二阶段：内化行动记忆

第二阶段对应的是 **经验内化阶段**。

当一类任务被反复执行之后，原本依赖外部材料的步骤、判断方式和行动顺序，会逐渐沉淀为内部记忆。

到了这个阶段，主体不需要每次都重新查找参考内容，而是可以直接根据已有经验进行思考，并推出下一步该做什么。

这一阶段的 Memory 更像是一种 **内化能力**。它的表现通常是：

- 不再强依赖外部材料
- 对步骤和顺序已经形成稳定理解
- 对常见情况有默认判断
- 可以根据上下文直接推出下一步行动
- 行动速度更快，成本更低

所以，第二阶段的核心作用是：

**把历史经验转化为可以直接驱动行动的内部能力。**

## 两个阶段的区别

| 维度 | 第一阶段：外部辅助记忆 | 第二阶段：内化行动记忆 |
| --- | --- | --- |
| 面对的任务 | 陌生任务 | 熟悉任务 |
| 主要依赖 | 外部材料 | 内部经验 |
| Memory 位置 | 环境中的参考物 | 主体内部的记忆结构 |
| 核心能力 | 检索、学习、执行 | 理解、压缩、推导 |
| 下一步如何产生 | 参考材料给出步骤 | 记忆直接支持推理 |
| 行动成本 | 较高 | 较低 |

## 两个阶段如何衔接

这两个阶段不是割裂的，而是一个连续的演化过程：

1. 在陌生任务中借助外部材料开始行动
2. 在执行过程中积累真实经验
3. 从经验中提炼出关键步骤、判断条件和有效策略
4. 把这些可复用的模式压缩为内部记忆
5. 在下一次类似任务中，直接由记忆支持思考和行动

换句话说：

**Memory 的价值，不只是保存过去，而是减少未来的重复学习。**

## 这对 Agent Memory 的启发

如果把这个模型放到 Agent 上，一个好的 Agent Memory 系统至少应该支持两类能力。

### 对第一阶段的支持

当 Agent 面对陌生任务时，它应该能够：

- 找到相关的外部参考材料
- 识别哪些材料值得信任
- 把参考内容整理成可执行步骤
- 在执行过程中记录发生了什么

### 对第二阶段的支持

当 Agent 反复完成同类任务后，它应该能够：

- 从历史执行中提炼稳定经验
- 区分一次性信息和可复用模式
- 把成功做法沉淀成长期记忆
- 在后续任务中优先调用这些记忆来推导下一步行动

所以我更关注的，不是：

- Agent 能存多少上下文

而是：

- Agent 能不能从一次次执行中形成自己的行动记忆

## 第一阶段 Memory 系统设计（草案）

上面定义的是第一阶段的方向。再往下走一步，第一阶段的 Memory 系统至少要回答一个更具体的问题：

**当 Agent 正在处理一件事时，系统应该怎样组织这件事的过程，才能让 Agent 高效知道这件事是什么、已经做到哪里、过去是怎么做的。**

### 1. 先有一个统一的组织单位

我目前的一个基本判断是：

**任何事情都应该以某种形式被组织起来。**

这里先不急着定义这种形式到底是任务、事项、案例还是工作流，当前可以先统一把它叫做 **Matter**。

也就是说：

- 平时做的任何一件事情，都应该归属于某个 Matter
- 一个 Matter 可以很短，很快完成
- 一个 Matter 也可以很长，跨越很多阶段和很多步骤
- 不管 Matter 长短，系统都应该能持续组织它的上下文和进展

这个判断很重要，因为如果没有统一的组织单位，Memory 就会退化成零散记录，Agent 很难知道“这些记录到底属于哪件事”。

### 2. 原始记录层：保存最权威的基础事实

一个好的第一阶段 Memory 系统，首先应该有 **原始记录层**。

这一层负责记录 Matter 在推进过程中发生的每一次关键事件和进展。它是整个系统最基础、也最权威的一层。

这一层的作用是：

- 记录真实发生过什么
- 记录进展是如何一步步形成的
- 为后续所有组织、总结和展示提供原始依据

所以，原始记录层更像是 Matter 的 **事实底稿**。后面所有更高级的结构，都应该建立在这一层之上，而不应该脱离它。

### 3. 组织层：把原始记录整理成可理解的结构

只有原始记录还不够，因为原始记录往往是连续的、细碎的、时间顺序驱动的。

系统还需要第二层能力：在原始记录的基础上，把这些内容重新组织起来，让它们变得更容易理解和使用。

这一层可以做的事情包括：

- 按 Matter 聚合记录
- 按时间梳理进展
- 提炼关键节点
- 标记当前状态
- 识别重要决策
- 识别阻碍和未解决问题
- 提炼下一步候选行动

这一步的重点不是“压缩成一句总结”，而是：

**把原始事件流整理成 Agent 可以操作的 Matter 结构。**

### 4. Matter Manager：第一阶段里的一个实验性实现

需要先说明一点：

**这个仓库的核心是 Agent Memory，不是 Matter Manager。**

`Matter Manager` 只是当前在第一阶段里，用来验证 Memory 如何组织、如何披露、如何被 Agent 使用的一种实验性实现。

它回答的是一个更局部的问题：

**如果第一阶段要围绕 Matter 来组织 Memory，那么系统可以怎么落地。**

所以这里写 `Matter Manager`，不是要把它定义成最终标准答案，而是把它当成一个可操作的实验样本。

它体现的不是一个单独的小功能，而是一整套组织方式：

- 任何持续推进的事情，都先归到某个 Matter
- 每个 Matter 都有自己的原始记录
- 所有 Matter 以树状结构被组织起来
- Agent 在需要时按层次查看，而不是一次性读完所有细节

这里的树状组织，至少包括两层：

- Matter 的分类
- 分类下的 Matter 名称

在这个结构上，再挂载每个 Matter 的原始信息和详细历史记录。

也就是说，`Matter Manager` 的核心作用，不只是“记一条记录”，而是：

**把零散事件组织成一个可追踪、可浏览、可逐层披露的 Matter 树。**

### 5. Agent 展示层：用 Agent 高效处理的形式呈现

在组织层之上，系统还需要一层 **Agent 展示层**。

因为“记录得下来”和“Agent 能高效使用”是两件不同的事。系统需要把已经组织好的内容，进一步转换成 Agent 熟悉、易检索、易推理的形式。

这层的形式目前不预设唯一答案，可以包括：

- 纯文本摘要
- 结构化文本
- 知识图谱
- 向量数据库 + Embedding
- 多种形式组合的混合表示

这里的关键不是用哪一种技术名词，而是：

**哪一种表示方式能让 Agent 在需要时最快拿到足够有用的 Memory。**

### 6. Matter 的披露策略：先粗后细地给 Agent 看

除了“存什么”和“怎么组织”，第一阶段还要解决一个很实际的问题：

**Agent 在真正需要读取某个 Matter 时，应该先看到什么，后看到什么。**

我目前的判断是，最合适的策略不是一次性把所有内容全给 Agent，而是按层次披露。

一个更高效的顺序可以是：

1. 先看 Matter 的分类
2. 再看 Matter 的名称
3. 再看 Matter 的原始信息（meta）
4. 最后在需要时再看详细历史记录

这样做的好处是：

- Agent 可以先快速定位当前是哪个 Matter
- 可以先用最小上下文理解 Matter 是什么
- 只有在需要细节时，才继续下钻到完整历史
- 可以减少不必要的上下文消耗

因此，`Matter Manager` 在第一阶段里的一个重要思想就是：

**先按树定位，再按层次披露，再在必要时进入详细历史。**

### 7. 获取策略层：在需要时拿到正确的 Memory

即使记录、组织、展示都做好了，如果 Agent 在真正执行任务时拿不到正确的内容，Memory 依然无法发挥作用。

所以第一阶段还必须有 **获取策略层**。

这一层关注的问题是：

- Agent 在当前任务里应该取回哪些 Memory
- 应该优先取原始记录、结构化结果，还是压缩后的表示
- 应该按当前 Matter 取回，还是按相似历史案例取回
- 应该返回完整上下文，还是只返回与当前动作最相关的局部内容

换句话说，Memory 不是“都存进去”就结束了，真正关键的是：

**在具体行动发生时，以合适的策略把合适的 Memory 交给 Agent。**

### 8. 第一阶段系统的整体结构

把上面几层放在一起，第一阶段的 Memory 系统可以先理解为这样一个结构：

1. 用 `Matter` 作为统一组织单位
2. 用原始记录层保存最基础的事实
3. 用组织层把事实整理成 Matter 结构
4. 用展示层把 Matter 结构转成 Agent 易处理的表示
5. 用披露策略控制 Agent 先看什么、后看什么
6. 用获取策略层在执行时返回最合适的 Memory

这意味着，第一阶段的重点不只是“存”，而是要形成一条完整链路：

**记录 -> 组织 -> 表示 -> 获取 -> 支持行动**

### 9. 当前对第一阶段的几个判断

目前我对第一阶段设计的判断是：

- Matter 应该是第一阶段最基本的组织单位
- 原始记录必须保留，它是整个系统的权威来源
- Matter Manager 只是当前用于验证第一阶段设计的一种实验性实现
- 组织层和展示层应该与原始记录分开
- 对 Agent 的披露应该是分层的，而不是一次性灌入全部历史
- 展示形式可以有多种，不应过早锁死
- 获取策略本身就是 Memory 系统的一部分，而不是一个附属问题

## 第二阶段 Memory 系统设计（草案）

如果说第一阶段解决的是 **如何借助外部 Memory 完成任务**，那么第二阶段要解决的就是：

**如何把第一阶段里积累下来的经验，真正内化到模型本身。**

我目前对第二阶段的一个核心设想是：

**第二阶段不是继续把经验存成外部材料，而是把这些经验通过后训练的方式，参数化到模型参数里。**

也就是说，第二阶段的重点不再是“把 Memory 放在外部给 Agent 查”，而是：

**让模型本身学会这些经验，并在推理时直接表现出来。**

### 1. 第二阶段的目标

第二阶段的目标是让模型在面对熟悉任务时：

- 不必每次都重新检索第一阶段的外部材料
- 能直接理解当前处境
- 能基于过去积累的经验推出下一步行动
- 在常见任务上表现出更稳定的行动习惯和判断方式

从这个角度看，第二阶段更像是把第一阶段的显式 Memory，逐渐变成模型内部的隐式能力。

### 2. 第二阶段的输入来自第一阶段

第二阶段并不是凭空产生的，它的训练素材应该主要来自第一阶段积累下来的内容。

这些内容包括：

- Matter 执行过程中的原始记录
- 被整理过的 Matter 结构
- 历史上有效的操作步骤
- 成功的行动轨迹
- 关键判断点和决策方式

换句话说，第一阶段更像是在 **积累训练材料**，而第二阶段则是在 **把这些材料变成模型能力**。

### 3. 第二阶段的核心动作：经验参数化

我目前的判断是，第二阶段最关键的一步是：

**把那些稳定、可复用、已经被验证过的经验，从外部记录中抽出来，再通过后训练写进模型参数。**

这意味着，不是所有第一阶段的原始记录都应该直接进入参数。

更适合被参数化的，应该是那些：

- 高频出现的模式
- 在多个 Matter 里反复验证有效的策略
- 比较稳定的步骤顺序
- 对下一步行动有明确指导价值的判断规则

因此，第二阶段不是简单地“把更多数据喂给模型”，而是要做一次经验筛选和压缩。

### 4. 可能的实现方式：Agentic RL

在训练方法上，我目前倾向于把第二阶段理解成一种 **后训练（post-training）问题**。

其中一个重要方向，就是使用 **Agentic RL** 这样的方式来训练模型。

这里的直觉是：

- 第一阶段已经积累了大量与真实任务相关的操作轨迹
- 第二阶段可以把这些轨迹变成训练环境、目标和反馈信号
- 模型通过训练，不只是“知道答案”，而是学会在任务过程中如何一步步行动

如果这样做成功，那么第二阶段得到的就不只是外部可查的 Memory，而是模型参数中真正具备的行动能力。

### 5. 第二阶段完成后会发生什么变化

当第二阶段足够成熟之后，Agent 的行为会发生一个重要变化：

- 面对熟悉任务时，优先依赖模型内部已经学到的能力
- 只有在陌生、罕见或不确定的情况下，才回到第一阶段的外部 Memory 系统

也就是说，第一阶段和第二阶段不是互相替代，而是形成分工：

- 第一阶段负责支持陌生任务和经验积累
- 第二阶段负责把成熟经验转化为低成本、高速度的内部能力

### 6. 当前对第二阶段的几个判断

目前我对第二阶段设计的判断是：

- 第二阶段的本质是经验内化，而不是外部存储扩张
- 第二阶段的关键目标是把经验参数化到模型参数里
- 第一阶段积累的 Matter 轨迹，是第二阶段最重要的训练来源
- 不是所有经验都适合参数化，应该优先内化稳定、可复用、已验证的模式
- Agentic RL 是一个很值得重点探索的训练方向
